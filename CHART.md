# Графики GBPUSD / EURUSD — эксплуатация и бюджет

## Новая доработка: достижение уровня и перенос сохранённых линий — 2026-10-23
- Новые алерты — одноразовое касание/пересечение уровня (`reach`), без ручного Above/Below в обеих формах. Чипы ручной формы: −50/−20/+20/+50 пипсов.
- Базой служит свежая торгуемая серверная цена при создании. Без неё алерт вооружается первым свежим тиком, не ретроспективно по кэшу. Равенство уровня срабатывает; скачок через уровень также срабатывает. Уведомление только по полученным ценам, не по OHLC: пропущенное движение при разрыве потока не гарантируется. База сохраняется в SQLite; нет записи на каждом тике.
- Старые выше/ниже не мигрируют молча: их условия сохранены и помечены legacy. Изменение уровня через PATCH переводит этот алерт на reach с новой свежей базой (или ожиданием свежего тика). ID, заметка и дата создания остаются. Сработавший/чужой алерт переносить нельзя.
- Сохранённую активную линию можно захватить пальцем/мышью (14 px), двигать и корректировать числом. Save alert изменяет тот же алерт; Cancel ничего не пишет. До Save сервер продолжает следить за старым уровнем; если он успел сработать, перенос отклоняется. Reset/смена инструмента или TF отменяет черновик. При выборе линии автомасштаб выключается до Reset view.
- Атрибуция с NOTICE, ссылкой TradingView и Apache 2.0 перенесена в читаемый footer страницы; встроенный логотип отключён штатной опцией. LICENSE/NOTICE файлы сохранены.
- Записи ниже — история этапов разработки графика, не новая проверка.

## Предыдущая клиентская доработка — 2026-10-23
- Внутри свечного поля вертикальный touch-свайп перемещает ценовой диапазон, не страницу: vertTouchDrag включён, touch-action:none, overscroll containment. За пределами графика страница прокручивается штатно. Ручной pan отключает autoScale; Reset view возвращает автомасштаб.
- Будущая (ещё не серверная) линия сплошная серая, перетаскивается пальцем/мышью с допуском 14 px. Открытая форма и Alert price сохраняются, значение обновляется при drag и ручном вводе. Save alert создаёт запись прежним POST API; движения сами по себе ничего не сохраняют. Работающие алерты по-прежнему выбираются/удаляются, без переноса их уровня.
- Сохранённые алерты также сплошные, текущая цена пунктирная. При пустом native-crosshair событии выбранная цена не сбрасывается.
- Load earlier удалена; история подгружается автоматически у левого края, Retry остаётся при ошибке. Атрибуция не удалена: README библиотеки 5.0.9 требует NOTICE и ссылку на доступной пользователю странице.
- Текущая проверка после финальных правок: npm test **79 pass / 1 skip**; Edge/CDP browser smoke **pass**, включая реальное изменение price range вертикальным свайпом без изменения scrollY страницы и touch-drag будущей линии. Физический телефон и production не проверены. Cloudflare-набор в этом этапе не запускался; его результаты ниже исторические. Деплоя не было.

## Возможности
- Графики есть у GBPUSD и EURUSD (свечи OANDA), DXY, GER40, XAUUSD и XAGUSD (свечи Capital.com); только M15/H1/H4/D1.
- Lightweight Charts 5.0.9 поставляется локально в public. Подписка, ключ TradingView и карта для библиотеки не нужны. Apache 2.0, notice и обязательная атрибуция сохранены.
- Приглушённые светлые/тёмные свечи, фитили, пунктир и метки в монохромной палитре приложения. Английский интерфейс без постоянных пояснений про источник и предварительную свечу.
- Обычный тап не создаёт уровень. Touch использует штатное удержание библиотеки (~240 мс), мышь — 500 мс; второй touch-таймер удалён. Удержание → движение перекрестия → плюс у правой шкалы → форма Add alert → числовая коррекция / above или below → отдельное подтверждение. До подтверждения серверный алерт не создаётся. Плюс видимым размером 26 px имеет touch-зону 44 px, остаётся после отпускания, не уходит за верх/низ панели.
- Для GBPUSD/EURUSD вся старая ручная форма свёрнута под Manual alert. Стрелка раскрывает/сворачивает её с обратимой анимацией высоты/прозрачности и поддержкой reduced-motion. Скрытые поля inert и недоступны с клавиатуры; на инструментах без графика форма открыта. Select alert не изменён.
- Расстояние между свечами ограничено 2–24 px; вертикальный диапазон — 1/5–5 от диапазона первого ручного drag (минимум 0.0002, верхний предел также ограничен положительными ценами). Reset view сбрасывает эту опорную величину. Инерция отключена. При удержании мышью pane-pan выключен; touch-tracking завершается на отпускании, следующий свайп снова pan. Обновление истории сохраняет вид по времени свечей; линия выбора обновляется без пересоздания.
- Панорамирование и pinch средствами библиотеки. Перетягивание правой шкалы меняет вертикальный диапазон; Reset view восстанавливает автомасштаб и последние свечи. Двойной клик по шкале также сбрасывает вид.
- Активные личные алерты отображаются линиями и в списке. Тап рядом с существующей линией или выбор из списка открывает Delete alert. Действия используют прежний защищённый POST/DELETE /api/alerts, лимиты, авторизацию и серверное отслеживание при закрытом приложении.
- Last price и Cached history появляются только при отсутствии свежей цены / восстановленной или устаревшей истории. Свежесть истории истекает локально через 90 секунд даже без ответа сети. При старой цене above/below не выбирается автоматически.
- Нет автоматического поиска ликвидности, уровней или сигналов.

## Данные и ограничения
GET /api/chart/candles?symbol=EURUSD&timeframe=M15[&before=unix_seconds]. Допустимы только шесть инструментов с графиком и четыре TF; проверяется авторизация и доступ к запрошенному инструменту. История не используется для срабатываний.

OANDA_ENV и OANDA_SIDE общие с серверным quote feed (сейчас practice/mid). OHLC — брокерские mid-свечи, текущая цена — существующий midpoint bid/ask. Полные экстремумы брокерской свечи и sampled stream не обязаны совпадать: текущая свеча предварительная, сверяется раз в минуту. Новая свеча появляется после ответа истории, возможна задержка до минуты; серверные алерты по потоку её не ждут. Это техническое ограничение описано здесь, а не постоянным пояснением на графике.

Дневное выравнивание 17:00 America/New_York с DST; время на графике UTC. Mid OHLC не вычисляются усреднением bid/ask OHLC.

| TF | Свечей на инструмент | Примерная глубина при пяти торговых днях в неделю |
|---|---:|---|
| M15 | 2000 | 4 торговые недели |
| H1 | 2000 | 16–17 торговых недель |
| H4 | 1500 | около года |
| D1 | 1000 | около 4 лет |

Это предел количества, не гарантия календарного покрытия. Клиент получает по 300 свечей и подгружает старые автоматически при прокрутке к левому краю. Первый запрос TF загружает ограниченную историю; последующие — последние 10 свечей с объединением, после долгого простоя — снова полный диапазон.

## Кэш и дополнительная нагрузка
- Один общий кэш на пару symbol/TF для всех пользователей, single-flight и не чаще одного OANDA-запроса в минуту на пару. GBP-кэш сохранён под прежними ключами; EUR имеет отдельные ключи. Неактивный график не опрашивает историю.
- Максимум 24 JSON-снимка (8 OANDA + 16 Capital) / до 39 000 свечей в SQLite. Оценка порядка 2–4 МБ сериализованных данных плюс SQLite/WAL/индексы; production-размер не измерялся. Персональные копии истории не создаются.
- После сбоя доступный снимок остаётся с отметкой Cached history, исходные timestamps не освежаются. На устройстве отдельный офлайн-кэш свечей не добавлен: после перезагрузки без сети история не гарантируется.
- Сценарий: 10 пользователей × 40 видимых минут = 400 пользовательских минут/день. Базовый Cloudflare UI: prices раз в секунду ≈24 000, events раз в 1,5 секунды ≈16 000 запросов/сутки.
- Один видимый график на пользователя: история и список алертов раз в минуту ≈800 дополнительных HTTP/сутки. EUR не удваивает минутный опрос клиента: одновременно выбран только один инструмент. Переключения, страницы, открытия и CRUD — дополнительно.
- Полная прокрутка четырёх TF обоих инструментов каждым из 10 пользователей: до 460 страниц истории (7+7+5+4 на инструмент), часть пересекается с периодическим опросом. Одновременные запросы к брокеру объединяются.
- Если все восемь symbol/TF востребованы круглосуточно: до 11 520 history fetch и логических SQLite SET/сутки плюс перезапуски. В сценарии 400 пользовательских минут при стабильном выборе — порядка до 400 обновлений; частые переключения добавляют. SET переписывает JSON, не отдельные свечные SQL-строки; фактические billed rows зависят от хранилища и индексов.
- Существующая REST reconciliation ≈8640/сутки плюс stream reconnect, H4 и Capital не ускоряется этим изменением. OANDA fetch — subrequests, не новые входящие Worker requests. Права и ограничения конкретного OANDA-аккаунта учитываются отдельно.
- Cron */5: 288 Worker/DO обращений в сутки. Окно stream до 540 с: около 160 alarms/сутки без горячих инструментов Capital; при активных алертах или открытом графике Capital окна короче (см. CLOUDFLARE.md). Известная основа — примерно 41,1 тыс. Worker и 41,25 тыс. DO запросов/сутки плюс статические файлы, Access, Telegram, открытия, News/Live/H4 и повторы. Это не полный верхний предел всего аккаунта.
- Один непрерывно активный DO при 128 MiB: около 11 059 GB-s/сутки, примерно 85% бесплатных 13 000. Duration не умножается на число одновременных пользователей; другие DO аккаунта уменьшают остаток. Новые DO, cron и платные услуги не добавлены.

## Квоты и риск бюджета $0
Ориентиры опубликованных Free-квот: Workers 100 000 запросов/сутки аккаунта, CPU 10 ms/request, 50 subrequests/request, 6 одновременных исходящих соединений. DO: 100 000 запросов/сутки с alarms, 13 000 GB-s/сутки, SQLite 5 млн прочитанных / 100 тыс. записанных строк/сутки, 5 GB хранения суммарно. Дневные квоты сбрасываются в 00:00 UTC; превышение Free может завершать операции ошибкой. Параметры тарифов могут меняться — сверять перед деплоем.

Гарантии бесплатной работы без ограничений нет. Смотреть Dashboard: requests, duration, CPU errors, rows read/written, storage, ошибки OANDA; отдельно учитывать Access/D1 и другие проекты аккаунта. Начальный разбор и запись 2000 свечей требуют production-проверки CPU. Локальные тесты не измеряют биллинг и квоты.

## Проверки и запуск
Node >=20; проверки запускаются на Node 24.
- `npm ci --ignore-scripts`
- `npm run test:cloudflare` — dry-run, не публикация. Сейчас 112 pass.
- `npm test` — 107 pass, 1 skip (Redis-тест без redis-server).
- `node test/chart-preview.mjs` — изолированный сервер: искусственные OANDA, настоящий локальный core/auth/CRUD/SQLite. Использовать URL из вывода. Ничего не отправляет Telegram и не обращается к боевому OANDA.
- `node test/chart-browser.mjs http://127.0.0.1:PORT` — браузерный smoke (playwright-core, установленный Edge), только URL локального стенда. Проверяет отсутствие draft от тапа, удержание/движение/плюс, EUR CRUD, реальное изменение price range при drag, эмуляцию touch-hold, четыре TF и переключение EUR/GBP. Сохраняет test/chart-revision.png. Это не физический телефон и не Telegram WebView.

Эти проверки не затрагивают реальную доставку Telegram, боевой OANDA, телефонные жесты и production-квоты.
